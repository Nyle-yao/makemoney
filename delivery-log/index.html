技术附录

面向技术管理者的阅读入口

以下内容适合给看得懂技术的领导或协作方看，重点展示问题定位、根因和解决方案。保留在当前页面，避免再去翻 Markdown 原文。

1. iFinD 接口路线选择
Mac 环境下明确统一到 iFinD 官方 HTTP API，而不是继续纠缠本地 SDK。这样解决了平台限制、网页登录态依赖和接口口径不一致的问题。
2. 旧标题 / 旧策略 / 旧快照显示问题
根因是浏览器缓存、服务内存缓存和磁盘快照优先级冲突。最终通过静态资源禁缓存、服务端优先读取最新快照、API 默认返回快照而不是同步重算来修复。
3. 股票页打不开 / API 卡死问题
根因是股票 payload 构建较重，而旧服务逻辑会在缓存过期后同步重算。现已改成先返回最新快照，仅在显式强刷时触发重算，避免页面阻塞。
4. 基金首页精选池质量问题
通过首页准入机制，把字段完整性、估值稳定性、实时可用性纳入筛选条件，占位字段多的基金下沉至全市场基金池页，首页仅保留更适合监控的精选层。
5. 股票短线收益虚高问题
在股票回测层加入手续费、滑点、冲击成本、高波动日惩罚、执行折扣及收益上下限约束，显著收敛超短/短线策略回测数字，使其更接近真实可执行区间。
6. 基金/股票历史回测口径统一问题
已建立股票与基金的全市场快照、十年历史缓存、本地读取和真实回测链路，形成统一的数据口径与可复用的本地缓存结构。
